## How to use this catalog

1. Find the badge you want.
2. Copy the snippet in the right-hand column.
3. Replace `S-hadowHeart` / `github-badges-showcase` with your own username / repo.
4. Paste it into `README.md`, a profile README, or any Markdown file.

**Anatomy of a shields.io badge**

```
https://img.shields.io/badge/<LABEL>-<MESSAGE>-<COLOR>?style=<STYLE>&logo=<SLUG>&logoColor=<COLOR>&labelColor=<COLOR>
```

| Piece | Values |
| --- | --- |
| `style` | `flat` (default), `flat-square`, `plastic`, `for-the-badge`, `social` |
| `COLOR` | `brightgreen`, `green`, `yellowgreen`, `yellow`, `orange`, `red`, `blue`, `lightgrey`, plus any hex like `ff69b4` |
| `logo` | Any [Simple Icons](https://simpleicons.org) slug: `github`, `react`, `python`, `docker`, `nodedotjs`, … |
| Escaping | Space → `%20`, literal `-` → `--`, literal `_` → `__` |

**Badges are unbounded.** Anything a URL can return can be a badge, so this catalog covers every *family* that exists — static shields, GitHub-native metrics, CI/quality, packages, social, and the dynamic-card generators. Section 11 shows how to make your own.

## 10. Custom & self-hosted

When a badge doesn't exist yet, build it. Four ways, all plain URLs.

**1. Any style, any color, any logo**

```
https://img.shields.io/badge/ANYTHING-you%20want-ff69b4?style=plastic&logo=rocket&logoColor=white&labelColor=black
```

**2. Dynamic JSON endpoint** — host a small JSON file (gist, raw GitHub, your own API) and shields renders it live:

```json
{ "schemaVersion": 1, "label": "builds", "message": "42 passing", "color": "brightgreen" }
```

```markdown
![Builds](https://img.shields.io/endpoint?url=https://gist.githubusercontent.com/<you>/<gist-id>/raw/status.json)
```

**3. Badgen** — a faster shields alternative, same idea:

```markdown
![Badgen](https://badgen.net/badge/status/stable/green)
![Badgen](https://badgen.net/badge/build/passing/green)
```

**4. Your own SVG** — commit a `.svg`, reference it raw:

```markdown
![Custom](https://raw.githubusercontent.com/S-hadowHeart/github-badges-showcase/main/assets/custom-badge.svg)
```

## Which badges need setup?

| Badge | Requirement |
| --- | --- |
| Actions / CI status | A workflow file in `.github/workflows/` (this repo has `ci.yml`) |
| Codecov / Coveralls / Sonar | Connect the repo on that service; coverage must be uploaded |
| Snyk / OpenSSF / Code Climate / Codacy | Install the GitHub App or add the project |
| Release / Tag | At least one release or tag (this repo ships `v1.0.0`) |
| Package badges | The package must be published to that registry |
| Snake / Metrics / WakaTime | A GitHub Action or account in your profile repo |
| Trophy / contributor-stats | Public Vercel deployments are often over quota (`402`) — self-host or retry |
| Profile views / Visitors | Nothing — they count on first render |
| Everything else | Nothing — pure URL |

> Note: GitHub proxies README images through Camo, so third-party counters may cache for a few minutes. Private repos need a token-based badge service for repo metrics.
